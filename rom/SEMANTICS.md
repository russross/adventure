ROM reconstruction and analysis
===============================

`adventure.bin` is the immutable 4,096-byte cartridge input with SHA-256 `b0326b45e5cab066b2d03f1e683708d82de3ffe60b2e968bf88c5494237f0a96`. Both assembly editions must reproduce every byte. `adventure.asm` preserves address labels; `adventure-gameplay.asm` gives the same code gameplay names and graphical comments. Neither source is generated by the analyzer.

`make -C rom` assembles both editions with DASM format 3 into grouped binary, listing, and symbol outputs under `build/`, then runs `tools/analyze.py` against the tracked cartridge to produce `build/control-flow.json`. A missing grouped output or changed source, tool, or Makefile regenerates the corresponding group. DASM defaults to `tools/dasm`; if unavailable or stale, Make downloads pinned v2.20.17, builds it under `tools/`, and copies the executable. An absolute `DASM` override selects another assembler.

`make -C rom check` synchronizes the local uv environment, checks Python formatting, lint, and types, then reconstructs and compares both binaries with the input. `tools/verify.py` checks basic-block coverage, call continuations, graphics separation and page containment, timing paths, referenced gameplay symbols, named control targets, and all graphical comments. Expected failures report a concise error and exit unsuccessfully. The detailed cartridge invariants are in [the project semantics](../SEMANTICS.md).

`mostlyclean` removes listings, symbols, analysis outputs, Python bytecode, and downloaded assembler build intermediates while preserving assembled binaries and the assembler executable. `clean` additionally removes `build/` and that executable. Neither modifies source, the cartridge input, Python configuration, lockfile, or persistent data. Rust consumers use crate-local symlinks to this directory's tracked cartridge and do not depend on reconstruction outputs.
